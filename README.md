# 3D RPG 战斗原型（RPG Game Prototype）

> Unity 3D 斜俯视角动作 RPG 原型，聚焦玩家战斗操作、敌人行为、房间状态与战后成长选择。  
> Unity 个人项目｜系统设计与程序实现

## 项目简介

本项目是一个以房间推进为核心的 3D RPG 战斗原型。玩家在斜俯视视角下移动并与敌人战斗，通过普通攻击、闪避和招架应对不同敌人行为。关卡数据负责指定敌人生成组，敌人通过目标更新、移动追击、技能选择与攻击执行构成基础行为循环；房间系统根据敌人清空或玩家死亡进入不同结算状态。

项目当前定位为用于验证战斗规则与系统结构的可玩原型，不代表完整商业化 RPG。当前数据包含 3 个关卡配置、3 类敌人、5 条敌人生成配置记录、4 条技能配置记录，以及 8 条战后强化配置。

## 当前版本内容

| 模块 | 当前配置 / 实现 |
|---|---|
| 关卡 | 3 个配置：遗迹入口、遗迹深处、遗迹核心 |
| 敌人 | 3 类：基础近战、远程、综合型敌人 |
| 敌人生成 | 5 条生成配置记录，按关卡生成组读取 |
| 技能 | 4 条配置：玩家普通攻击、敌人普通近战、蓄力重击、普通远程攻击 |
| 强化 | 8 条强化配置，战后提供最多 3 个不重复选项 |
| 房间状态 | Ready、InProgress、Cleared、Failed |

## 核心玩法循环

```text
进入关卡
  → 读取 Luban 关卡与生成组配置
  → 生成敌人
  → 房间进入 InProgress
  → 玩家移动 / 普通攻击 / 闪避 / 招架
  → 敌人索敌、追击、选择技能并执行攻击
  → 敌人全部被击败：Cleared
  → 玩家生命归零：Failed
  → 展示对应结算与重试 / 前进入口
```

## 玩家操作

| 操作 | PC 输入 | 手柄 / 移动端 |
|---|---|---|
| 移动 | WASD | 手柄左摇杆 / 移动端虚拟摇杆 |
| 普通攻击 | J / 鼠标左键 | 手柄或移动端攻击按钮 |
| 闪避 | Shift / 鼠标右键 | 手柄按键 |
| 招架 | K | 手柄按键 |

> 具体按键绑定以当前 Input System 配置和运行版本为准。

## 战斗与敌人行为设计

- **玩家战斗：** 普通攻击通过攻击组件和技能配置执行；闪避按配置距离、冷却与持续时间移动，并在闪避期间处理受击判定；招架用于应对敌人的特殊攻击窗口。
- **敌人行为：** 使用 Unity Behavior 自定义 Action，拆分目标更新、移动到目标、选择可用技能和执行攻击等职责；移动与追击使用 NavMesh 相关组件。
- **技能时间轴：** 技能配置包含伤害、触发范围、冷却、前摇、预警、有效时间、后摇和硬直等参数。敌人蓄力重击具有明显的前摇/预警窗口，成功招架可打断攻击并使敌人进入硬直。
- **房间管理：** `RoomCombatManager` 维护存活敌人集合和玩家死亡监听，控制 Ready、InProgress、Cleared、Failed 状态及胜负结算。

## 关卡与数据驱动

关卡、敌人、技能和强化数据通过 Luban 生成的 JSON 配置读取，主要数据表如下：

| 数据表 | 管理内容 |
|---|---|
| `TbLevel` | 关卡名称、下一关 ID、场景名、生成组 ID |
| `TbLevelSpawn` | 生成组、敌人类型、数量和生成半径 |
| `TbEnemy` | 敌人生命、移动速度、索敌范围和技能 ID |
| `TbRole` | 玩家生命、移动与闪避参数 |
| `TbSkill` | 攻击伤害、范围、冷却及技能时间参数 |
| `TbUpgrade` | 强化类型、效果数值、权重、解锁关卡与叠加上限 |

同一个 `spawn_group_id` 下的配置记录由生成服务读取并在当前房间初始化时生成；当前实现不是逐波清怪后再生成下一波的波次系统。

## 战后强化选择

当前强化模块从 Luban 强化表中筛选可用选项，过滤尚未解锁或已达到叠加上限的强化，并按权重随机提供最多 3 个不重复选项。玩家选择后，效果应用到对应角色属性或战斗组件；单局重开时重置本局强化记录。

当前强化表包含 8 项效果：普通攻击伤害、攻击间隔、攻击判定范围、最大生命值、伤害减免、招架窗口、闪避冷却和移动速度。当前数据中的稀有度、权重与解锁等级分布较简单，后续可继续扩展平衡设计。

## 如何打开项目

1. 安装 Unity `6000.5.10f1`。
2. 在 Unity Hub 中选择 **Add project from disk**。
3. 选择仓库中的 `RPGUnityProgram` 文件夹。
4. 等待 Unity 导入资源并解析 Package Manager 依赖。
5. 打开项目场景；检查 NavMesh 烘焙、Prefab 引用及 Luban 配置加载是否正常。

## 当前开发边界与后续方向

当前重点是验证玩家基础操作、敌人近战/远程/特殊攻击行为、招架窗口、房间胜负管理、数据驱动关卡和战后强化选择。项目仍属于战斗原型，后续可继续完善敌人种类、关卡内容、战斗反馈、强化池差异、数值平衡与移动端适配；未完成的规划功能不计入当前已实现内容。
